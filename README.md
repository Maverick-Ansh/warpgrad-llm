# WarpGrad from scratch, and applied to language models

A from-scratch reproduction of **[Meta-Learning with Warped Gradient Descent](https://arxiv.org/abs/1909.00025)**
(Flennerhag, Rusu, Pascanu, Visin, Yin, Hadsell. ICLR 2020), followed by a port
of the method to language modelling.

Nothing here is imported from the authors' code. Every equation is implemented
from the paper text, and every module quotes the line it implements.

---

## What the paper says, in one paragraph

You want a neural network to learn a new task fast. One way is to learn a good
starting point for its weights, which is what MAML does. Another way is to learn
a better *update rule*. WarpGrad takes the second route, but with a trick that
makes it cheap.

Instead of learning a big matrix that corrects the gradient, WarpGrad inserts
extra layers, called **warp-layers**, in between the network's normal layers.
During the backward pass the gradient has to travel back through those extra
layers, and each one multiplies it by that layer's Jacobian. So the gradient
that reaches a normal layer has already been multiplied by a product of matrices
that the meta-learner controls. That product **is** the correction. You never
build it, never store it, and never invert it. You add some layers and call
`.backward()`.

The second idea is what makes it scale. MAML-style methods differentiate through
the entire training run, which gets expensive and unstable past a handful of
steps. WarpGrad does not. It treats the points visited during training as
samples, takes one step from a sampled point, asks whether that step helped, and
nudges the warp-layers to make it help more. The training run is only a device
for producing points to ask the question at. That is why the cost does not grow
with the number of adaptation steps.

## Layout

```
warpgrad/
  geometry.py     explicit warp Omega, metric G^-1 (Section 2.3, Eq. 7-9)
  warp.py         implicit warp-layers (Eq. 6) and the Table 3 capacity ladder
synthetic/
  mountain.py     Appendix D's randomised loss surfaces
  train_mountain.py  Algorithm 1, with Eq. 11 (exact) and Eq. 12 (approximate)
  check_warp.py   GATE: coverage, bracket, degenerate shortcut
  evaluate.py     bracketed comparison against gradient descent
  make_figures.py Figure 3 and Figure 7
  sweep.py        the one hyper-parameter Appendix D does not give us
llm/
  model.py        byte-level GPT written from scratch, warp-layers interleaved
  data.py         p(tau) = one language per task, 25 meta-train, 7 meta-test
  bracket.py      GATE: per-language floors, because bits-per-byte lies
  oracle.py       GATE: per-language ceiling and the no-meta-learning baseline
  meta.py         WarpGrad, Leap, Reptile, joint training
  train.py        Algorithm 2 (offline) with Algorithm 1 as a flag
tests/            14 smoke tests that assert the paper's rules
REPORT.md         the actual deliverable: claims, what broke, verdicts
```

## Run it

```bash
pip install -r requirements.txt
python tests/test_mountain.py && python tests/test_warp.py

# the mountain
python synthetic/train_mountain.py --meta-steps 100 --warp-init residual
python synthetic/check_warp.py --warp results/mountain/warp_residual_peaks_exact_s0.pt \
       --warp-init residual                      # GATE, refuses if ill-posed
python synthetic/make_figures.py --warp results/mountain/warp_residual_peaks_exact_s0.pt \
       --warp-init residual

# the language tier
python llm/oracle.py                             # GATE, run this first
python llm/train.py --arm warp_leap --warp-kind linear
python llm/train.py --arm leap                   # the control that isolates the warp
```

A Colab notebook that runs the whole thing on 2x T4 is described in REPORT.md.

## Two things worth knowing before reading the numbers

**The evaluation broke before the model did.** Twice. The first version of the
synthetic experiment reported that WarpGrad *loses* to plain gradient descent,
with a win rate of 17 percent. That number was an artefact: the warp could only
reach 25 percent of the domain that initial points are drawn from, so for three
quarters of the comparisons the two optimisers were starting from different
places on the surface. Both `check_warp.py` and `bracket.py` exist to catch that
class of mistake, and both will refuse to run a sweep on an instrument that
cannot measure. The full story is in REPORT.md, section "What broke".

**Bits per byte is not comparable across writing systems.** UTF-8 uses one byte
per character for Latin and three for Georgian, Tamil and Devanagari, and two of
every three bytes in a three-byte script are continuation bytes that are nearly
free to predict. A model can score well on Tamil while knowing no Tamil. Every
number in this repository is normalised against that language's own floor and
its own ceiling, both measured on that language's own data.
